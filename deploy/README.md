# deploy — развёртывание NEXO

## Что внутри (этап Э1)
| Служба | Назначение |
|---|---|
| `postgres` | PostgreSQL 16 + WAL-G; схема создаётся из `db/migrations` при первом запуске |
| `redis` | кэш, лимиты, список отозванных сессий |
| `minio` | оперативное хранилище файлов (бакет `nexo-media`) и локальная цель копий (`nexo-backups`) |
| `backup` | ежесуточно: полная копия WAL-G + логическая копия (pg_dump → age); WAL архивируется непрерывно |

Сервис приложения и Caddy добавляются в ветке с сервером.

## Первый запуск (на своём компьютере или сервере)
1. Установить Docker Desktop (Mac/Windows) или Docker Engine (Linux).
2. В папке `deploy` скопировать `.env.example` в `.env`, заполнить все `СМЕНИТЬ` (подсказки в файле).
3. Создать ключ age на ВАШЕМ компьютере: `age-keygen -o nexo-age.key`. Строку `Public key:` вставить в `AGE_RECIPIENT`. Файл ключа сохранить вне сервера (менеджер паролей, флешка).
4. `docker compose up -d --build`
5. Проверить: `docker compose ps` (все `healthy`/`running`), `docker compose logs backup` — должна быть строка «готово» для первой копии.

## Резервные копии
- **Физические (WAL-G)**: полная копия раз в сутки (03:00 UTC), WAL — непрерывно (не реже чем раз в 5 минут): цель RPO ≤ 5 минут. Хранится 30 полных копий. Данные шифруются ключом `WALG_LIBSODIUM_KEY`.
- **Логические (pg_dump + age)**: независимая копия раз в сутки, шифруется открытым ключом, расшифровывается только вашим закрытым ключом. Выгрузка во внешнее S3 включается `OFFSITE_ENABLED=true`.
- **Важно**: пока цель копий — локальный MinIO на том же сервере, это не защита от потери сервера. В боевой среде укажите внешнее S3 другого провайдера.

## Проверка восстановления (раз в месяц обязательно)
```
docker compose exec -u postgres backup /scripts/verify-restore.sh
```
Скрипт поднимает временный экземпляр из последней копии и проверяет, что в схеме `nexo` есть 40 таблиц. Рабочую БД не трогает.

## Восстановление после аварии
1. Остановить приложение; на чистом томе поднять `postgres` без данных.
2. Физически: `wal-g backup-fetch <каталог> LATEST`, создать `recovery.signal`, `restore_command='wal-g wal-fetch %f %p'`, запустить PostgreSQL (точка во времени: `recovery_target_time`).
3. Логически: `restore-logical.sh <файл.dump.age> nexo-age.key <имя_базы>`.
Ключи (`WALG_LIBSODIUM_KEY`, закрытый ключ age) нужны в обоих случаях.
