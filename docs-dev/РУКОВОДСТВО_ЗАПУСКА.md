# NEXO, этап Э1: как собрать и запустить (JetBrains Rider, macOS)

Все действия с git выполняются в интерфейсе Rider. Консоль нужна только для `docker compose` (команды можно вставить во вкладку **Terminal** внизу окна Rider).

## 0. Что должно быть установлено
1. **Rider** (у вас есть). 2. **.NET SDK 10**: Rider → Settings → Build, Execution, Deployment → Toolset and Build покажет версию; если SDK 10 нет, скачайте с dotnet.microsoft.com/download. 3. **Docker Desktop** (для сервера и базы).

## 1. Получить код (ветки лежат на GitHub)
Этап разложен на ветки, каждая основана на предыдущей: `stage1/db-docker-backups` → `stage1/server` → `stage1/client`. Последняя содержит всё.

1. Rider → **Git → Fetch** (или значок «Update Project», синяя стрелка). Новые ветки появятся в списке.
2. Внизу справа нажмите на название ветки → **Remote Branches → origin → stage1/client → Checkout**.
3. Проверка: в дереве проекта (Explorer) есть `NEXO.sln`, папки `src`, `deploy`, `db`, `proto`.

## 2. Собрать
1. Откройте `NEXO.sln` (File → Open → выберите файл → Open as Solution). Rider сам скачает пакеты NuGet (внизу индикатор «Restoring…»).
2. Меню **Build → Build Solution**. Если появились ошибки — **не исправляйте вручную**, скопируйте окно Build (или сделайте скриншот) и пришлите мне: код писался без возможности собрать его в моей среде, первые ошибки компиляции ожидаемы.
3. Тесты ядра: правый клик по `tests/Nexo.Core.Tests` → **Run**. Ожидается «Пройдено: 18, провалено: 0».

## 3. Запустить базу и сервер в Docker
1. Откройте Terminal в Rider, перейдите в папку: `cd deploy`.
2. `cp .env.example .env` — создаст файл настроек. Откройте `deploy/.env` в Rider и замените все значения `СМЕНИТЬ…`:
   - пароли: в Terminal выполните `openssl rand -hex 24` и вставьте результат (для `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `MINIO_ROOT_PASSWORD`; тот же пароль MinIO в `WALG_S3_SECRET_KEY`);
   - `WALG_LIBSODIUM_KEY`: `openssl rand -hex 32`;
   - `NEXO_KEK_BASE64` и `NEXO_FAKE_KDF_SECRET_BASE64`: `openssl rand -base64 32` (два разных значения);
   - `AGE_RECIPIENT`: установите `brew install age`, выполните `age-keygen -o ~/nexo-age.key`, вставьте строку «Public key: age1…». Файл `nexo-age.key` сохраните вне проекта — он нужен для восстановления логических копий.
   - **Сохраните копию `.env` в менеджере паролей**: без ключей копии БД и секреты не расшифровать.
3. `docker compose up -d --build` — первый запуск займёт несколько минут (собирается образ сервера).
4. Проверка: `docker compose ps` — все сервисы `running/healthy`; `curl -k https://localhost/health` отвечает `{"status":"ok"}`.
5. Резервные копии: полная копия каждый день в 03:00 UTC, WAL-архив непрерывно (потеря не более 5 минут), логическая копия `pg_dump` + age. Проверка восстановления: `docker compose exec -u postgres backup /scripts/verify-restore.sh` (подробности в `deploy/README.md`). В боевой среде обязательно настройте внешнее S3 (`OFFSITE_*`).

## 4. Запустить клиент
1. В Rider выберите конфигурацию запуска **Nexo.Client.Desktop** (выпадающий список справа вверху) и нажмите зелёный треугольник.
2. На экране входа укажите адрес сервера. Самый простой путь для проверки на своём компьютере — запустить Docker с файлом для разработки (раздел 5) и ввести `http://localhost:5080`. Для `https://localhost` через Caddy macOS должна доверять его локальному сертификату: выполните `docker compose exec caddy caddy trust` в папке `deploy`.
3. **Регистрация**: ник, имя, пароль (не короче 10 символов) → отметьте согласие → «Создать». **Запишите ключ восстановления** и отметьте галочку.
4. Для проверки переписки запустите вторую копию клиента (Run ещё раз под другой учётной записью) и найдите первого пользователя по нику (строка поиска, Ctrl/⌘+K).
5. Вход с нового устройства: зарегистрированный пользователь входит на втором экземпляре; на первом появится плашка «Новое устройство просит войти» с кодом — сверьте и подтвердите.

## 5. Запуск для разработки (порты наружу) и отладка сервера из Rider
1. Запуск всего с открытыми портами: в `deploy` выполните `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build`. Сервер доступен клиенту по `http://localhost:5080`.
2. Чтобы отлаживать сервер в Rider, а не в контейнере: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres redis minio`; откройте `src/Nexo.Server/appsettings.Development.json` и впишите `POSTGRES_PASSWORD` из `deploy/.env`; запустите конфигурацию **Nexo.Server** (профиль Development: секреты и ключ подписи создаются сами в папке `data`, она в .gitignore). Адрес для клиента тот же: сервер слушает gRPC на 5080.
3. Остановить: `docker compose down` (данные сохраняются в томах; `down -v` удалит их вместе с базой).

## 6. Слияние в dev и main (только после проверки)
1. Git → Branches → **dev** → Checkout.
2. Правый клик по `origin/stage1/client` → **Merge 'origin/stage1/client' into 'dev'**.
3. Git → Push. Затем на GitHub можно удалить ветки задач. В `main` сливайте `dev` только после закрытия этапа Э1 (приёмка по `06_ПМИ`).

## Что входит в этап Э1 и что отложено
Готово: регистрация без телефона и почты, вход, ключ восстановления, восстановление, подтверждение входа с нового устройства, список и отзыв устройств, личные чаты, сообщения (текст, ответы, правка 48 ч, удаление, прочтение, «печатает»), синхронизация между устройствами и после обрыва, очередь отправки офлайн, автоудаление по таймеру (серверная часть), приватность и блокировки (серверная часть), шифрованная локальная БД, PIN, автоблокировка, горячие клавиши, резервные копии БД.
Отложено по плану: группы и каналы, медиа, закрепление и реакции, поиск по сообщениям, TOTP (Э2); секретные чаты (Э3); звонки (Э4); платформенные хранилища ключей и биометрия, веб-клиент, мобильные платформы.
