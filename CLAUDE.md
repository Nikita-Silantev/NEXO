# NEXO — правила для ИИ-ассистента и разработчика

Проект: кроссплатформенный мессенджер NEXO. Документация в папке `Документы/` — **нормативная**: код подчиняется документам, а не наоборот.

## Порядок работы
1. Перед любой задачей прочитать раздел документов, к которому она относится (см. таблицу ниже).
2. Если задача требует отклонения от документов — НЕ делать молча: сначала предложить изменение документа, получить согласие владельца, изменить документ, затем код.
3. Работать по этапам Э1–Э6 (см. `07_План_и_правила_разработки`). Мобильные платформы — в конце. Не опережать этап.
4. Один этап = набор требований из ТЗ (колонка «Этап»). Не добавлять функций вне ТЗ.

## Жёсткие правила
- Контракт API — только `proto/*.proto`. Не менять поля без изменения `04_Описание_протокола`. Номера полей не переиспользовать.
- Схема БД — только `schema.sql`; изменения через миграции и обновление `05_Описание_модели_данных`.
- Пароль и MasterKey никогда не уходят на сервер и не пишутся в журналы. Токены, ключи и содержимое сообщений в журналы не пишутся.
- Собственных криптографических примитивов не писать: libsodium и BCL по таблице из `03_Криптография`.
- Секретные чаты недоступны в веб-клиенте.
- Фильтр запрещённых слов применяется только к тексту статуса, не к сообщениям.
- Любая ошибка API — код gRPC + `ErrorDetail` (см. отображение причин в документе протокола).
- Каждое изменение сопровождается тестом; крипто-функции — тестовыми векторами.

## Стек
C# / .NET, Avalonia (+ReactiveUI) для всех клиентов, ASP.NET Core (модульный монолит), PostgreSQL 16, Redis, MinIO (+внешний S3 как холодное хранилище), LiveKit, Docker Compose, Caddy.

## Владелец и работа с git
Владелец работает с git только через интерфейс Visual Studio. Код отдавать готовыми файлами и с подробной пошаговой инструкцией, какие файлы куда положить и что нажать. Общение — по-русски.

## Перед завершением задачи
- Сверить с таблицей требований: какие коды ТЗ закрыты.
- Прогнать проверки согласованности (см. раздел «Проверки» плана).
- Если изменилось поведение — обновить затронутые документы и ведомость версий.
